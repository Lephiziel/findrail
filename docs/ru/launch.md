# План запуска Findrail

## Что продаём первым пользователям

«Найди нужный фрагмент в своих заметках, коде и текстовых PDF. Без загрузки
документов в облако и без AI-подписки». Первый сегмент для проверки — разработчики
с Markdown-заметками, локальными репозиториями и техническими PDF. Это гипотеза
аудитории, а не доказанное преимущество над существующими поисковиками.

Альфа умеет локальный поиск, предпросмотр, страницы PDF и автообновление. Эти
четыре вещи должны быть понятны до чтения архитектуры. Подключённые сервисы,
семантический поиск и MCP описываем отдельно как будущие возможности.

## Порядок на первые 30 дней

| Период | Действие | Что должно получиться |
|---|---|---|
| Дни 1–3 | Проверить архивы на чистых компьютерах, пройти установку по README | Список реальных препятствий установки и исправления |
| Дни 4–7 | Записать 45–60 секунд демо; пригласить 10–15 добровольных тестировщиков | Люди установили приложение и нашли свой документ |
| Неделя 2 | Разобрать неудачные поиски, ошибки PDF и обновления | Улучшения по наблюдениям, выпуск следующей альфы |
| Неделя 3 | Опубликовать демонстрацию в одном подходящем сообществе; отвечать на вопросы | Осмысленные отзывы и новые самостоятельные установки |
| Неделя 4 | Сделать технический разбор, добавить задачи для контрибьюторов | Проверить повторное использование и первые внешние вклады |

Это последовательность работы, не обещание сроков или числа звёзд. Не нужно
одновременно размещать одинаковый пост на десятках площадок: каждое сообщество
должно получить подходящую ему демонстрацию и ответы автора.

## Сценарий демонстрации

1. Показать две выбранные папки: Markdown / код и текстовый PDF. Использовать
   только синтетические или публичные документы; имена и пути тоже не личные.
2. Ввести слово, найденное на второй странице PDF. Открыть Preview, показать
   страницу и Copy location с `#page=2`.
3. Найти фрагмент заметки, изменить его в редакторе и показать обновлённую выдачу.
4. Завершить двумя командами запуска и ссылкой на готовые архивы.

Не демонстрировать сканированный PDF как поддерживаемый OCR, поиск по смыслу
как существующую функцию или ещё не написанный GitHub-коннектор.

## Первые тестировщики

Автор самостоятельно предлагает тест людям, у которых уже есть подходящая
задача. Здесь нет отправленной рассылки или автоматических обращений.

Попросить выполнить три действия: установить без подсказок, найти два знакомых
фрагмента в своей папке, вернуться к приложению через несколько дней. Записать
добровольную обратную связь: где остановились, нашли ли оригинал, зачем вернулись.
Не просить присылать приватные документы или полные поисковые запросы; для бага
достаточно обезличенного описания или синтетического воспроизведения.

Рабочие ориентиры на месяц: 15 попробовали, минимум 10 нашли нужный документ,
минимум 5 вернулись через неделю. Это выбранные цели эксперимента, а не прогноз.
Если установка или поиск регулярно проваливаются, следующая работа — исправить
эти сбои перед широкой публикацией.

## Репозиторий, который помогает попробовать и участвовать

README должен начинаться с задачи пользователя, затем давать архив и две
команды запуска. Уже добавлены английская и русская документация, инструкции,
синтетический smoke-сценарий, CI и сборка архивов. Записанное демо ещё нужно
добавить после прогона на реальных компьютерах.

Предлагаемые GitHub topics: `golang`, `local-first`, `search`, `sqlite`,
`markdown`, `pdf`, `self-hosted`. Это предложения для настройки, не утверждение,
что topics уже установлены.

Создать несколько небольших issues с понятным результатом: доступность
интерфейса, пример русскоязычных поисковых задач, проверка установки на ARM,
синтетические PDF с разными шрифтами. Ставить `good first issue` только задачам,
которые реально подходят новичку. GitHub использует эту метку для поиска и
подбора возможностей участия; метка не гарантирует приход контрибьюторов.

## Что измерять

В текущем приложении нет телеметрии. Для первой проверки достаточно добровольных
интервью и отчётов, а для публичных данных — GitHub issues / PR / releases.

Главные показатели: установка завершена, время до первого найденного документа,
успешность двух задач, возвращение через неделю, исправленные препятствия и
внешние вклады. Звёзды считать отдельно: интерес к репозиторию полезен, но не
заменяет использование. Платный трафик пока не нужен: сначала проверяем, что
небольшая группа людей регулярно получает пользу.

## Черновик анонса

**Findrail: local search for notes, code and text PDFs**

I’m building Findrail, an open-source Go app for finding remembered words in
folders of notes, source code and text PDFs. Results include matching passages,
a saved-text preview and the original location; PDF matches preserve page
numbers. Selected folders refresh while the app runs. No AI account or document
upload is required.

The first local alpha has installation archives for Linux, macOS and Windows.
It uses SQLite FTS5 and a read-only loopback interface. OCR, cloud connectors and
semantic search are not included yet. I’m looking for feedback on installation,
missed keyword matches and folder refresh, especially reproducible examples
using synthetic documents.

Repository and releases: https://github.com/Lephiziel/findrail

черновик, он никуда не отправлен. Для Show HN префикс заголовка: `Show HN:`.
