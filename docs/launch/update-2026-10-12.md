## Delivery order

1. Freeze the candidate feature set. Update release notes and installation /
   upgrade guidance to schema 6 and the actually included commands.
2. Exercise one downloaded/extracted candidate: empty start, add folder,
   text/PDF/DOCX search, collect exact evidence, export Markdown, restart.
   Preserve the stopped-directory backup/rollback instructions.
3. Publish a deliberately versioned new release and verify the actual archives,
   checksums and metadata. VERSION changes trigger the existing release path;
   this documentation change neither changes VERSION nor publishes a release.
4. Build and distribute the compatible VSIX as an explicit asset with server
   requirements and uninstall steps. Do not imply Marketplace distribution.
5. Submit the verified workflow to Console, Terminal Trove and Changelog,
   respecting any prior submission. Keep the old recording labelled as the
   older local-search demo.
6. Use voluntary installation, actual document recovery and return-use
   reports to choose the next improvement. Five independent successful starts
   are an experiment target, not a forecast.

The primary developer scenario is: search selected technical notes, code and
text documents, inspect an original passage, and export explicitly collected
citations as Markdown. CLI, MCP, editor and snapshot workflows are optional
entry points, not required steps in that first demonstration.
