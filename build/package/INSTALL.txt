Findrail local alpha — https://github.com/Lephiziel/findrail

Choose the archive matching your operating system and CPU (Linux/macOS x86-64
or ARM64; Windows x86-64). Download SHA256SUMS.txt beside the archive. Compute
the downloaded archive's hash, then compare it with the row for the exact same
archive basename in SHA256SUMS.txt:
  Linux:   sha256sum "findrail_<version>_<target>.tar.gz"
  macOS:   shasum -a 256 "findrail_<version>_<target>.tar.gz"
  Windows: (Get-FileHash -Algorithm SHA256 -LiteralPath ".\findrail_<version>_<target>.zip").Hash
Keep the archive and BUILD-INFO.json if you need to report a problem. Candidate
archives are unsigned.

Extract the archive to a directory you own. Go, Python, an external database,
and an installed service are not required at runtime. Options go before
positional arguments.

Try the fictional demo first:
  Linux/macOS: ./findrail demo --no-open
  Windows PowerShell: .\findrail.exe demo --no-open
Search for “idempotency”; the PDF evidence is on page 2. Ctrl+C stops the demo.

Start an empty local index and open the printed loopback URL:
  ./findrail start --no-open
Then use Add folder or Add GitHub in Sources. GitHub snapshots are public,
commit-pinned and refreshed manually. Supported local inputs include bounded
text, text PDFs (no OCR), and bounded DOCX body text. Legacy folders upgraded
from older indexes keep DOCX disabled until explicitly enabled in Configure.
Original files are never altered. serve and MCP are read-only.

Run `findrail doctor --json` for a shareable diagnostic with local paths
redacted. `--show-paths` explicitly includes your data-directory path. The index
contains plaintext extracted text and original paths; protect it like your
documents. No telemetry is sent.

Default index directory:
  Linux:   $XDG_DATA_HOME/findrail, or ~/.local/share/findrail
  macOS:   ~/Library/Application Support/Findrail
  Windows: %LOCALAPPDATA%\Findrail
Use the same `--data-dir DIR` for start, index, search and serve.

Before upgrading, stop every Findrail process. Copy the entire data directory,
including any SQLite WAL/SHM auxiliary files, to a separate backup location.
Use the path configured for your installation; these examples quote paths with
spaces and use a destination separate from the originals:
  Linux:   cp -a "$HOME/.local/share/findrail" "$HOME/findrail backup"
  macOS:   cp -a "$HOME/Library/Application Support/Findrail" "$HOME/Findrail backup"
  Windows PowerShell: Copy-Item -LiteralPath "$env:LOCALAPPDATA\Findrail" -Destination "$env:USERPROFILE\Findrail backup" -Recurse

Then start using the new binary; supported migrations run on first write. To
roll back, stop Findrail and restore the complete backup directory to a new
location, then use a binary compatible with that backup's schema. Do not run an
older binary against a schema-4 index; reverse migrations are not supported.

To uninstall, stop Findrail and remove the extracted application directory.
Optionally remove the index directory separately if you no longer want its
plaintext indexed copy. This does not remove or alter original files.

macOS packages are unsigned and unnotarized; platform security may warn or block
them. Do not disable system-wide protections. Alpha limitations include no OCR,
manual GitHub refresh and a plaintext local index. No daemon is installed.
