PACKAGE IDENTITY
Read BUILD-INFO.json for the exact application version, source revision, target
and SQLite schema. A source-built or CI/rehearsal archive is not a published
release; download public packages and checksums only from the actual GitHub
release page. Published alpha.5 uses schema 8; alpha.4 uses schema 7 and alpha.3
uses schema 6. Alpha.4 binaries cannot open schema 8. The public release tag,
manifest and checksums identify the published bytes; a later source/CI build is
not a replacement for that immutable release.

INSTALL A PUBLISHED STANDALONE ARCHIVE
1. From the GitHub Releases page, download the archive for your OS/CPU and the
   SHA256SUMS.txt from that same release. Match the exact archive basename.
2. Verify the checksum before extraction:
   Linux:   sha256sum "findrail_<version>_<target>.tar.gz"
   macOS:   shasum -a 256 "findrail_<version>_<target>.tar.gz"
   Windows PowerShell:
     (Get-FileHash -Algorithm SHA256 -LiteralPath ".\findrail_<version>_<target>.zip").Hash
   Compare the printed hash with the matching row in SHA256SUMS.txt. Stop if it
   differs. Checksums detect transfer errors; they are not a publisher signature.
3. Extract the archive into a directory owned by your account. Paths may contain
   spaces; quote them in commands. Go, Python, a database server and an installed
   service are not required at runtime.

DESKTOP LAUNCHER (alpha.4 and alpha.5 archives)
The five platform archives include the ordinary `findrail` CLI and the
separate `findrail-desktop` launcher. It acquires ownership of the chosen data
directory before opening SQLite. Starting it again opens the verified existing
loopback endpoint rather than creating a second server. Closing a browser tab does
not stop Findrail; use the UI Quit action or stop the owning process.

Install for the current user from the extracted archive:
  Linux: launcher/linux/install-user.sh; remove the menu entry with
    launcher/linux/uninstall-user.sh.
  macOS: launcher/macos/install-user.sh copies Findrail.app to ~/Applications;
    launcher/macos/uninstall-user.sh removes that app.
    The macOS app requires macOS 13 or newer, matching its Go 1.27 build.
  Windows: run launcher/windows/install-user.ps1 in PowerShell; remove its
    Start-menu shortcut with launcher/windows/uninstall-user.ps1.
These scripts do not delete indexed data. On Linux and Windows, the desktop
launcher can also be run directly. On macOS, launch Findrail.app. Uninstalling
the app is separate from deleting the data directory.
Install/update replaces only a Findrail resource recognized as Findrail-owned;
an unrelated file, symlink, or app/shortcut is left untouched and causes a
refusal. Linux and macOS installers stage the new resource before publishing it.
Existing alpha.4 Linux menu entries and macOS bundles are recognized by their
Findrail identity. An older unmarked Windows shortcut is recognized only when
its target and working directory match the packaged Findrail launcher layout.
If ownership cannot be established, inspect the resource and remove or rename it
yourself before retrying. Uninstall is safe to repeat and removes only a
recognized Findrail launcher resource; it never removes indexed data or source
documents. Platform menu caches may update asynchronously; installation is not
a transaction with the OS shell.

For Linux/macOS, an extracted path with spaces works as, for example:
  "/home/alex/Apps/Findrail alpha"/findrail start --no-open
  "/Users/Alex/Applications/Findrail alpha"/findrail start --no-open
On Windows PowerShell:
  & "$env:USERPROFILE\Apps\Findrail alpha\findrail.exe" start --no-open

The index contains plaintext extracted text and source paths and is not encrypted
at rest. There is no runtime telemetry. Protect the data directory like your
documents. The app binds to loopback; do not expose it to a network.

DATA LOCATION
Default data directory:
  Linux:   $XDG_DATA_HOME/findrail, or ~/.local/share/findrail
  macOS:   ~/Library/Application Support/Findrail
  Windows: %LOCALAPPDATA%\Findrail
If you configured --data-dir, use that exact directory for backup and restore.
The index is separate from the extracted application directory.

UPGRADE / BACKUP / ROLLBACK
The older alpha.2 binary uses schema 2. Published alpha.3 uses schema 6; the
alpha.4 uses schema 7 with forward migrations 1–7 (001_init,
002_local_alpha, 003_github_snapshots, 004_docx_policy, 005_archive_sources,
006_indexing_reports, 007_evidence_collections). Migrations run forward on the new binary's first write;
there are no reverse migrations. Legacy schema-2 sources keep DOCX disabled by
default; enable it explicitly per source before rescanning if desired.
Alpha.5 adds migration 008 and uses schema 8, adding saved
passage-window offsets to collections. Opening a schema-7 alpha.4 index with the
alpha.5 binary migrates it forward; the alpha.4 binary must not be used on
that upgraded directory. The upgrade path is tested against a real alpha.4
binary and a complete stopped backup. Restore that backup with its matching
binary if rollback is needed.

Before any upgrade, stop every Findrail process that could open this index. Stop
the server with Ctrl+C; also close any other CLI/client process using that data
directory. Then copy the COMPLETE data directory to a separate location, keeping
all files including findrail.db, findrail.db-wal and findrail.db-shm when present.
Use the actual configured path if it differs from the defaults. Examples:
  Linux:
    cp -a "$HOME/.local/share/findrail" "$HOME/findrail backup"
  macOS:
    cp -a "$HOME/Library/Application Support/Findrail" "$HOME/Findrail backup"
  Windows PowerShell:
    Copy-Item -LiteralPath "$env:LOCALAPPDATA\Findrail" -Destination "$env:USERPROFILE\Findrail backup" -Recurse
Do not put the backup inside the data directory being copied. Check that the
backup contains the database and any WAL/SHM files before opening the new binary.

Never point an older binary at a newer schema: alpha.2/schema 2 cannot open
schema 6, published alpha.3/schema 6 cannot open schema 7, and published
alpha.4/schema 7 cannot open schema 8. For rollback, stop
every Findrail process, preserve the upgraded directory separately, and restore
the WHOLE pre-upgrade backup to a different directory. Run the older compatible
binary against that restored copy (set --data-dir to that copy if needed). Do not
copy only the main SQLite database, mix backup files with the upgraded directory,
or expect a downgrade migration. Reverse migrations do not exist.

STOP AND UNINSTALL
Stop the running server with Ctrl+C and close all other Findrail processes. No
daemon or service is installed. Remove the extracted application directory using
your file manager (or the exact directory you chose). To remove indexed copies,
separately delete the data directory only after confirming its path and that you
no longer need it. This does not delete, change or uninstall your original files.
Keep or delete a rollback backup deliberately; it contains plaintext indexed
content and provenance.

PLATFORM / FEATURE LIMITS
Archives are unsigned. On macOS, Gatekeeper may warn or block first launch; use
only the app-specific option offered by macOS Privacy & Security if you choose to
allow this binary. Do not disable Gatekeeper or other system-wide protections.
This does not claim notarization, Gatekeeper approval, or Finder certification.
Scanned/image-only PDFs have no OCR. Search is lexical, not semantic. Public
GitHub refresh is manual. The optional VS Code VSIX is distributed separately
from the application archive; use the asset listed on the release page.
Marketplace/Open VSX publication is not included. The VSIX requires a compatible
Findrail server/client API v1; it is not needed for the first-run web workflow.
